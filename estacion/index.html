La Estación
del Antojo.

A wings, burgers and hot dogs restaurant in Iztacalco, Mexico City. I took it onto the delivery apps: the menu is live on Rappi, published on DiDi Food and set up on Google Maps. Every platform wants titles, descriptions, photos, taxes and fees for each of ~52 items, and each one takes a different commission. So I built a price calculator that keeps the restaurant's net the same everywhere, a copywriting skill for the menu, and Claude skills that fill the DiDi Food panel from a Google Sheet, because DiDi has no API for that.

Same net on every platform

Platforms charge different commissions, and on top of that the restaurant pays IVA on the commission and gets ISR withheld. If you copy the in-store price, you lose money on every order; if you add a flat percentage, you lose it on some platforms and overcharge on others. The calculator grosses each price up per platform so what the restaurant receives matches the in-store price.

platform price = in-store price / (1 − (commission + IVA + ISR))

The Sheet has one tab per platform (Rappi, DiDi with delivery, DiDi pickup, Uber Eats), a tab for modifiers like extra dressing or meat, a variant that simulates the IVA credit, and a column tracking whether each item already has its photo published on each platform.

Updating the DiDi Food menu from a Sheet

DiDi Food Manager is a web panel: dozens of products, around ten fields each, toggles and confirmation modals. I wrote two Claude skills that drive it through Claude in Chrome, using the catalog tab of the calculator as the source of truth.

  • Bulk update: the whole menu in one run
    Reads the entire Sheet first and builds a SKU → title → description → price → category map. Confirms which fields to apply (photo, title and description, pickup and delivery fees, IVA 16%, IEPS 0, sellable on its own, schedule), then creates one task per category so progress is visible and walks the menu product by product. It checks each toggle on screen before saving, logs exceptions like a missing photo without stopping, and ends with a count per category against the listing view.
  • Single update: one or two products
    A lighter skill for day-to-day changes: a price, a fee, a photo, a description, or turning a product off. Splitting it from the bulk skill keeps small edits cheap in tokens.
  • UI quirks written down
    A reference file documents what the panel does in production: toggles that need a double click, a product type that is locked for existing combos, a combo price that can't be 0, the hidden file input used for photo upload and the stable edit URL per product. It also loads all the Chrome tools in a single call to save tokens.

One voice across every app

  • A copywriting skill for ~52 items
    Rules for titles (clear, with piece count, sentence case, like "6 Nuggets de pollo con papas") and short third-person descriptions, no emojis, the same text for Rappi, DiDi, Uber Eats and print. It also catches typos in the source catalog. The rewritten titles are the ones customers see on Rappi today.
  • Checking whether the combos are a deal
    I priced each combo against its items bought separately, at a prorated price per piece. The best one saved the customer 23.4% (2 bacon hot dogs, 6 wings and fries: $180 vs $235), the weakest only 8.3% ($220 vs $240), with assumptions written down and the best one flagged to check margin.
  • Google Maps business profile
    Set up the profile with storefront photos so people nearby can find the place outside the delivery apps.
